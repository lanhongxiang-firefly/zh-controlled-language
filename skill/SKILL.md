# 中文受控语言 · Skill 执行层

本文件只负责加载与调度，不承载规则正文。规则、术语、示例与核对点按下方路由按需读取。

## 1 默认行为

直接完成任务。不主动汇报采用的模式、规则编号、修改过程、校验结论或自我评价。用户要求审查记录时，按 `core/quality-control.md` 第 4 节模板输出。原文已准确、自然、简洁时，直接交付，不作修改。

## 2 加载契约

1. 读取 `defaults.yaml` 的 `default_domain`，得到本次会话的默认学科；公开版该字段为空时，等待使用者首次配置。
2. 单次任务默认加载该学科 Pack，不需重复声明；用户明确要求时临时切换到其他学科，切换只影响本次任务。
3. 校验每个模块的 `manifest.yaml`：`id`、`core_version`（当前 Core 规则版本 `0.2`）、`enabled`；`enabled: false` 或版本不匹配的模块拒绝加载并记录原因。
4. 构建本次会话的模块白名单；判定只引用白名单内条目。配置缺失且用户未指定时，只加载 Core，不推断专业术语规范。
5. 允许同时加载多个 Pack 与多个 Profile；两者为正交维度。
6. 未加载的 Pack 内容不得被引用；学科未知时不推断专业术语规范。
7. 判定优先级：Core Error ＞ 已加载且状态为 `Accepted` 的 Pack 条目 ＞ Profile 的 Suggestion ＞ 未加载内容。
8. 术语冲突时保留各词形与上下文、登记「待确认」，不强制统一；状态为 `Proposed`／`Disputed`、依据类别空缺或依据不足时保留原词，不创造译法。

## 3 模块路由

| 需要 | 读取 |
| --- | --- |
| 通用语言规则、分级、误判控制、表达问题词形 | `core/language-rules.md` |
| 术语治理机制、依据类别、状态机、缩写与符号通用规则 | `core/terminology-governance.md` |
| 原文保护清单、按需核对点、误判类型、校准示例 | `core/quality-control.md` |
| 学科术语、准则数、学科特有规则与用例 | `domains/<id>/`（`manifest.yaml`、`terminology.md`、`rules.md`、`tests/cases.json`） |
| 文体适用强度与表达偏好 | `profiles/<id>/profile.md` |
| 技能名称与兼容别名 | `ALIASES.md` |

Core 始终加载，其 Error 级始终生效。Core 不引用任何 Pack 内容；Pack 不重复定义 Core 已有规则。

## 4 判定顺序

先确认是否属于保留项或正确表达 → 再判 Error（必须纠正且只作最小改动）→ 再判 Warning（建议；语境可解释时记「待确认」、不改写）→ Suggestion 默认不改。

## 5 交互边界

- 不为展示规则而制造改写。
- 原文无问题时不输出「未发现问题」式过程说明。
- 已归档版本不追溯修改；术语变更须登记「原词形 → 新词形」，仅在用户要求审查记录时输出。
- 本 Skill 只约束语言表达，不规定或假定任何具体技术、方法、模型、设备、软件或工具。
