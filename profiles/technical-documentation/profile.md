# 文体规范：技术文档与使用手册

> 第一版唯一示例 Profile。只调整适用强度与表达偏好，不含术语、译法、学科约束或 Error 级规则。字段定义见 `docs/architecture/pack-interface.md` 第 7 节。

## 适用强度

| 级别 | 本 Profile 下是否生效 | 说明 |
| --- | --- | --- |
| Error | 始终生效 | Core 的原文保护与真实错误纠正 |
| Warning | 生效 | 翻译腔、歧义、冗余与逻辑问题按语境提示 |
| Suggestion | 默认不改 | 由上下文决定 |

`strength = error-only` 时仅 Core 的 Error 生效，对应日常专业交流；本 Profile 取 `full`。

## 覆盖文本类型（迁移自 V0.2「适用范围与适用强度」）

覆盖：代码注释、技术文档、科研申请书、技术报告、项目材料、日志与错误提示、日常技术交流。

| 场景 | 文本类型 | 适用强度 |
| --- | --- | --- |
| 科研与工程技术 | 实验规程、数据说明、设计与计算说明、论文稿件、科研申请书、技术报告、图纸附注、图表题注、验收文档 | 完整（三级均适用） |
| 研发实现 | 代码注释、接口与约束说明、面向用户的日志与错误提示 | Error 完整；Warning 按可读性；Suggestion 一般不适用 |
| 项目与协作 | 任务书、立项与结题材料、阶段汇报、会议纪要、评审意见、风险与变更记录、往来函件技术段落 | 完整 |
| 日常专业交流 | 技术解释、任务汇报、答疑、对话中的技术说明 | 仅 Error；风格项不适用 |

下列对象不适用：引用原文与转录文本、法规与标准条文原文、公式与数学推导、图表原有标注、代码标识符与字符串、专有名称与型号编号、已归档版本、宣传与文学性文案。

适用强度按场景递减；日常交流不得套用文档模板或强制统一词形。

## 信息组织偏好（Suggestion，由文体与读者决定）

- 结论是否前置、段落划分、标题层级、清单颗粒度。
- 技术报告宜写明条件、依据与结论边界；申请书文体由评审要求决定，不设句段模板。

## 表达偏好（Suggestion，默认不改）

- 人称、第二人称、语气强度、情态词择一、铺垫语。
- 标点全半角、中西文留白、引号样式按项目约定。

## 正例与边界案例

1.（技术文档）「在壁面温度低于给定上限且辐射传热可忽略的条件下，按稳态导热关联式计算通过多层平壁的热流密度。」→ 不修改。依据：长句承载完整条件。
2.（日志与错误提示）「你可以在结果页查看每次测量的偏差。」→ 不修改。依据：第二人称由界面文体决定。
3.（日常技术交流）「这组数据先按上一版的方法处理，等标定结果出来再定系数。」→ 不修改。依据：日常交流仅适用 Error 级。

## 禁止事项

- 不定义术语、译法、缩写或学科特有规则。
- 不规定句长、段落长度、标题层级等硬性阈值。
- 不覆盖或削弱 Core 的 Error 级保护。
